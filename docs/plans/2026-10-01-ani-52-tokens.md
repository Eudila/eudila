# ANI-52 · Plan de implementación de tokens

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Centralizar la identidad de la app Next.js en Tailwind, mostrarla en `/tokens` y cerrar ANI-52 después de verificar los criterios originales.

**Architecture:** Ampliar el `@theme` existente en `app/globals.css`, usando variables CSS y utilidades nativas de Tailwind 4. El inicio y una página de muestras estática consumen los mismos tokens. No hay generador, catálogo externo, librería visual ni copia de valores de color en componentes.

**Tech Stack:** Next.js App Router, TypeScript, Tailwind CSS 4; una comprobación ejecutable con Python/Playwright como la que ya usa el prototipo.

## Contexto y decisiones

- ANI-52 es urgente, corresponde a M1 y no tiene dependencias pendientes. Base: `b2ee6e5`, scaffold de ANI-48 ya publicado y verificado. Se conserva la asignación a Joaco.
- El brandbook v1.0 y ANI-58 ya existen: se cargan sus valores reales. El PDF de uso interno permanece fuera del repo público.
- Las flores heredadas no se incorporan: el brandbook vigente define un orbe y el repositorio limpio excluye esos assets. Los colores de los siete estados se contrastan con el prototipo publicado.
- La regla de valores centralizados se verifica en la app Next.js. `prototype/` sigue siendo una referencia independiente que se integra en sus tareas existentes.
- El pedido incluye planificación y ejecución hasta Done. Se resuelven las decisiones de implementación dentro de ese alcance, sin pedir otra aprobación del diseño.

## 1. Definir los tokens y eliminar valores sueltos

**Modificar:** `app/globals.css`, `app/page.tsx`.

1. Definir primario institucional, acción derivada del primario, Nube/Grafito/Niebla, superficie, texto, borde y blanco.
2. Definir acento, orbe, ambiente y texto sobre acento para cada uno de los siete estados. Conservar los tonos de marca; usar Grafito en los acentos azul, turquesa y coral porque blanco no alcanza 4,5:1.
3. Definir tipografía, pesos, tamaños, interlíneas, espaciado base y áreas táctiles, anchos de composición, tracking, radios y sombra.
4. Usar `@theme static` para que las variables de la galería existan aunque se referencien desde estilos con `var(...)`.
5. Sustituir las clases de medidas arbitrarias del inicio por utilidades de tokens; mantener el texto existente y aplicar los tamaños del brandbook.

**Comprobación:** no hay hexadecimales ni medidas arbitrarias en los componentes de `app/`. Colores y medidas tienen una sola definición.

## 2. Mostrar toda la identidad

**Crear:** `app/tokens/page.tsx`.

1. Página estática con título propio, enlace al inicio y secciones de paleta, siete estados, tipografía, espaciado, composición, radios y sombra.
2. Mostrar muestras y nombres de variables, sin duplicar sus valores en TypeScript. Las muestras usan `var(...)`, también para tamaños y radios.
3. Cada color tiene una etiqueta visible. Las muestras decorativas se ocultan a lectores de pantalla; las acciones reales tienen foco visible y área táctil suficiente.
4. Probar 320, 390, 520 y 1280 px, con texto al 100 % y 200 %. Ninguna muestra debe provocar desborde horizontal.

## 3. Dejar una comprobación útil

**Crear:** `app/tokens/tokens.test.py`.

1. Reutilizar Python estándar y Playwright, sin nuevas dependencias de la app. La comprobación levanta su propio servidor Next.js y lo cierra al terminar.
2. Comprobar HTTP 200, título, fuente y cobertura de todas las variables definidas en el CSS.
3. Medir contraste de texto/acciones/estados desde los colores realmente calculados por el navegador; objetivo mínimo 4,5:1.
4. Cambiar la variable primaria en el navegador y comprobar que la muestra y su acción derivada cambian sin modificar componentes. Comprobar que las dos rutas reciben el tema común.
5. Comprobar reflujo, teclado, ausencia de errores JS y ausencia de valores sueltos en componentes.

**Comando:** `uv run --with playwright python app/tokens/tokens.test.py`.
